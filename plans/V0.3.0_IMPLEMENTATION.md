## Shared contracts

Final shape of the changed types in [`src/shared/ipc.ts`](../src/shared/ipc.ts):

```ts
/** Folder names from the Project down: ['Python', 'Setup', 'Install']. A Project is one name. */
export type ItemPath = string[]

export type ItemKind = 'group' | 'tutorial'

export interface TreeNode {
  kind: ItemKind
  name: string
  /** Groups only. Groups first, then Tutorials, each newest first. */
  children?: TreeNode[]
}

export interface ProjectNode {
  name: string
  children: TreeNode[]
}

export interface SettingsState {
  projectsFolder: string | null
  projectsFolderProblem: string | null
  /** Path of the selected Tutorial, or null when none is selected or it no longer exists. */
  selectedTutorial: ItemPath | null
  /** Keys (paths joined with '/') of the expanded Projects and Groups. */
  expanded: string[]
}

export type CreateAction = 'tutorial' | 'group'
```

`TutorialRef`, `TutorialNode` and `expandedProjects` are removed. `ImageItem`, `NameResult`, `RowAction`, `RecorderStatus` and `PermissionsStatus` are unchanged.

New in [`src/shared/paths.ts`](../src/shared/paths.ts) (pure, no imports):

```ts
export const pathKey = (path: ItemPath): string => path.join('/')
/** True when `inner` is `outer` or inside it. */
export function isWithin(inner: ItemPath, outer: ItemPath): boolean
/** `path` with the prefix `from` replaced by `to` (for renames and moves), or `path` unchanged. */
export function replacePrefix(path: ItemPath, from: ItemPath, to: ItemPath): ItemPath
export const parentOf = (path: ItemPath): ItemPath => path.slice(0, -1)
export function isItemPath(value: unknown): value is ItemPath // non-empty array of non-empty strings
```

Channels: see [V0.3.0_PLAN.md §3](V0.3.0_PLAN.md#ipc-contract-changes). Every argument path is checked with `isItemPath` in `ipc.ts`, then segment by segment in `projects.ts`.

## M2 — Groups on disk

### 2.1 Classification and the tree

`projects.ts`:

```ts
export const GROUP_TAG = '.tuto-group'
/** G3, in order: tag → group; an image → tutorial; a visible subfolder → group; else tutorial. */
export async function classify(folder: string): Promise<ItemKind>
```

- One `readdir(folder, { withFileTypes: true })` per folder: check for the tag, then for an image file, then for a visible, non-link subfolder.
- `listTree()` recurses into Groups only (Tutorials' subfolders are ignored), sorting each level Groups first, then Tutorials, each newest first then by name. A level that cannot be read lists as empty. Recursion stops at 64 levels as a guard (links are never followed, so there are no cycles).
- `resolve(path)` stays kind-agnostic; `tutorialPath(path)` additionally requires `classify` to say `tutorial` and the path to have at least 2 segments; a new private `containerPath(path)` requires a Project (length 1) or a Group.

### 2.2 Create, rename, trash, count

- `createItem(parent, kind, name)`: `containerPath(parent)`, `validateName` against the parent's entries, `mkdir`; for a Group also write an empty `GROUP_TAG` file. If writing the tag fails, remove the new folder and return the error.
- `rename(path, to)`: any path of length ≥ 1 (Projects included), same rules as v0.2.
- `countTutorials(path)`: Tutorials at any depth below a Project or Group (0 for a Tutorial).
- `trash(path)`: any path.

### 2.3 Move

```ts
/** Moves the Tutorial or Group at `path` into the Project or Group `destination`. */
move(path: ItemPath, destination: ItemPath): Promise<NameResult>
```

In order: `path` has at least 2 segments (Projects cannot move) and resolves; `destination` is a container (`containerPath`); `destination` is not within `path` ("A Group can't go inside itself."); `parentOf(path)` equals `destination` → `{ error: null }` and nothing happens; `validateName(name, destination's entries)` → "That name is already used in "…"."; `rename(old, new)`. An `EXDEV` error becomes "Can't move between disks." Other errors go through `readableError`.

- Tests (`tests/projects.test.ts`, real temp folders): every `classify` rule and their order (tag beats images, images beat subfolders, a link is not a subfolder, hidden subfolders don't count); a v0.2 layout lists unchanged; recursive tree and its order at depth 3; `createItem` Group writes the tag; rename and trash at depth; `countTutorials` recursive; `move` into a Group, into another Project, refused cases (Project, into itself, into its child, onto a Tutorial, name taken, current parent is a no-op).

### 2.4 IPC

- `items:create` handles `group`; `items:move` → `projects.move`, then `settings.followMove(path, [...destination, name])` on success; `items:trash` confirmation counts with `countTutorials` ("Move the Group "Setup" and its 4 Tutorials to the Trash?").
- `menu.ts`: `showCreateActions(sender, x, y)` → `'tutorial' | 'group' | null` (native menu: **New Tutorial**, **New Group**); channel `menu:create-actions`.
- Docs: `src/main/README.md` (projects table, classification, move, ADR 0003 link), `src/shared/README.md`.

**✅ Check (dev):** the tree from `projects:list` matches a hand-made folder layout with tagged, untagged, empty and image-holding folders.

**Code done (2026-11-21), manual check pending.** Notes:

- `move` checks a name clash by comparing names ignoring case, not with `validateName`: a folder made in Finder may hold characters (such as `:`) that the app would refuse for a new name but that must still be movable.
- `rename(path, to)` handles Projects too (the parent of a one-name path is the Projects folder).
- `items:trash` words the confirmation by kind: "the Tutorial … and its screenshots", or "the Group/Project … and its N Tutorials".

```ts
  kind: 'project' | 'group' | 'tutorial' | 'new'

  draft

```

- Recursive; a container being added to is shown expanded; the new row goes first among its siblings (before the Groups).
- Tests: depth 3 rows and depths; expanded keys at depth; new Group row inside a Group; rename of a Group; siblings for each editing kind at depth.

### 3.2 Sidebar DOM

- Indent: `item.style.setProperty('--depth', String(row.depth))`, with `padding-left: calc(6px + var(--depth) * 16px)` in `sidebar.css` (the CSSOM is allowed by the CSP; a `style` attribute in markup is not).
- Group rows: chevron and a stacked-folder icon (`.icon-group`, a CSS mask like the folder icon), **+** and ⋯ on hover.
- **+** on a Project or Group calls `window.api.showCreateActions(point)`; the choice starts editing `{ kind: 'new', parent, what }` and expands the container.
- `main.ts`: `commit()` calls `createProject` or `createItem(parent, what, name)`; a new Tutorial is selected, a new Group is expanded.

## M4 — Drag and drop

### 4.1 Rules

`treeView.ts`:

```ts
/** Whether `source` (a Tutorial or Group) may be dropped onto `target` (a Project or Group row). */
export function canDrop(source: SidebarRow, target: SidebarRow): boolean
```

False when: the source is a Project or a new row; the target is a Tutorial or a new row; the target is within the source (`isWithin`); the target is the source's current parent. Name clashes are left to main (the destination's children are not all in the row list when collapsed).

- Tests: every case above, plus a valid move into another Project.

### 4.2 Sidebar DOM

- Tutorial and Group rows are `draggable`, except while editing. `dragstart` sets a private type, `application/x-tuto-item`, with the path key, and remembers the source row.
- `dragover` on a row: `preventDefault()` only when the drag has that type and `canDrop` is true, so drops from Finder or other apps are never accepted. The accepting row gets `.drop-target`.
- Hover-to-expand: entering a collapsed container starts a 600 ms timer that expands it (through the same `setExpanded` as a click); leaving the row cancels it.
- `drop` → handler `move(sourcePath, targetPath)`; `dragend` clears the highlight and the timer.
- `main.ts`: `move` calls `window.api.moveItem(path, destination)`; an error shows in the status line; on success the destination is expanded and the tree refreshed (the selection already followed in main).
- No drag while a Recording runs (the window is hidden anyway) or while a name is being edited.
- CSS: `.row.drop-target` (accent outline), `.row.dragging` (dimmed).
- Docs: `src/renderer/src/sidebar/README.md` (drag and drop section and its rules).

**✅ Check:** the drag cases in the manual checklist in [V0.3.0_PLAN.md §5](V0.3.0_PLAN.md#5-testing).
