# tuto-record — v0.2.0 Plan: Projects, Tutorials and the new window

v0.2.0 replaces the single Output folder with **Projects** and **Tutorials**, and replaces the one-column window with a sidebar and a preview of the selected Tutorial's Screenshots. Recording itself (Clicks, Captures, Marker, Dock rule) does not change.

- **Vocabulary:** Projects folder, Project, Tutorial, Recording, Click, Capture, Screenshot and Marker are defined in [GLOSSARY.md](../GLOSSARY.md). **Output folder** is retired.
- **Decisions:** [ADR 0002](../docs/adr/0002-folders-are-the-only-record.md) (folders are the only record). [ADR 0001](../docs/adr/0001-capture-just-after-click.md) still applies.
- **Previous plan:** [MVP_PLAN.md](MVP_PLAN.md) (v0.1).

| D1  | Folder layout          | `<Projects folder>/<Project>/<Tutorial>/<Screenshots>`. Screenshot file names are unchanged (`YYYY-MM-DD_HH-mm-ss-SSS_d<N>.png`)                                                                                                                                                                                                                                                          |
| D2  | Source of truth        | Folders on disk are the only record ([ADR 0002](../docs/adr/0002-folders-are-the-only-record.md)). A folder's name is the Project's or Tutorial's name; names are unique within their parent, ignoring case                                                                                                                                                                               |
| D3  | Projects folder        | Must be chosen before recording; there is no default. v0.1's `outputFolder` setting is ignored, and its Screenshots stay where they are                                                                                                                                                                                                                                                   |
| D4  | Recording a Tutorial   | A Tutorial holds the Screenshots of one Recording. **Start recording** is offered only when the selected Tutorial is empty                                                                                                                                                                                                                                                                |
| D5  | Record again           | Shown when the Tutorial has images. Asks for confirmation, then moves **every image** in the Tutorial folder to the Trash as soon as Start is pressed, then starts the Recording                                                                                                                                                                                                          |
| D6  | Sidebar                | A tree: Projects expand to show their Tutorials. Both levels sorted **newest first** by folder creation time. Selecting a Tutorial shows its preview; Projects are not selectable, only expandable                                                                                                                                                                                        |
| D7  | Creating               | **+** next to PROJECTS adds a Project; **+** on a Project row adds a Tutorial in it. A new row appears with an editable name: Enter creates the folder, Esc cancels. Invalid names show an inline error                                                                                                                                                                                   |
| D8  | Rename and delete      | A **⋯** action menu on each Project and Tutorial row: **Rename** (inline, same rules as creating) and **Move to Trash** (confirmation, then the whole folder goes to the Trash)                                                                                                                                                                                                           |
| D9  | Remembered state       | The selected Tutorial and the expanded Projects are stored in settings. A selection whose folder is gone is cleared                                                                                                                                                                                                                                                                       |
| D10 | Preview                | Heading `Project › Tutorial`. A large view of the selected image and a horizontally scrolling strip of thumbnails under it. No chevrons; the large image does nothing when clicked                                                                                                                                                                                                        |
| D11 | Navigation             | Click a thumbnail, or ←/→, to select. The selected thumbnail is outlined and scrolled into view. Arrows stop at the ends (no wrap) and are ignored while a name field has focus                                                                                                                                                                                                           |
| D12 | What the preview shows | Every image file (png, jpg, jpeg, gif, webp) directly in the Tutorial folder, including ones the app did not make, one tile per file, sorted by file name (so app Screenshots come out in Click order, d1 before d2). Subfolders are ignored                                                                                                                                              |
| D13 | Removing a Screenshot  | A ✕ in the thumbnail's top-right corner on hover, or Delete/Backspace on the selected one. Asks "Move to Trash?", then moves the file to the macOS Trash                                                                                                                                                                                                                                  |
| D14 | Empty Tutorial         | "No screenshots yet", a short explanation and **Start recording** in the middle of the preview                                                                                                                                                                                                                                                                                            |
| D15 | Settings window        | A separate window, opened from a gear at the bottom of the sidebar or with **⌘,**. Holds the Projects folder (path, **Choose…**, **Open in Finder**) and the permission panel (with Relaunch). Opens by itself at launch when a permission is missing or no usable Projects folder is set; the main window then shows a notice with an **Open Settings** button and recording is disabled |
| D16 | Shortcut               | **⌃⌥⌘R** stops a Recording. When idle it only brings the main window forward; it never starts a Recording                                                                                                                                                                                                                                                                                 |
| D17 | Confirmations          | Native macOS dialogs (`dialog.showMessageBox`), shown by the main process                                                                                                                                                                                                                                                                                                                 |
| D18 | Status                 | The status line (ready, errors, shortcut warning) stays, under the preview header                                                                                                                                                                                                                                                                                                         |
| D19 | Renderer stack         | Plain TypeScript, no framework. One folder per UI module, each with a pure view builder (unit-tested), a thin DOM file and a README                                                                                                                                                                                                                                                       |

### Out of scope for v0.2.0

- Adding Screenshots to a Tutorial that already has some (only Record again)
- A full-size image viewer; reordering, annotating or exporting Screenshots
- Moving Tutorials between Projects; drag and drop; search
- Undo (the Trash is the undo)
- Windows and Linux

## 2. User flows

### First launch (or after an upgrade from v0.1)

1. The main window opens, with an empty sidebar and a notice: "Choose a Projects folder" and/or "Permissions needed", with **Open Settings**.
2. The Settings window opens by itself. The permission prompts work as in v0.1.
3. The user chooses a Projects folder. The Settings window can be closed; the main window refreshes on its next poll.

### Making a Tutorial

1. **+** next to PROJECTS → a new editable row → type "Python" → Enter. A `Python` folder is created and the row is expanded.
2. **+** on the Python row → type "How to install Python" → Enter. The folder is created and the new Tutorial is selected.
3. The preview shows the empty state with **Start recording**.

### Recording

1. **Start recording**. The main window and the Settings window (if open) hide, and Recording works as in v0.1, saving into the selected Tutorial's folder.
2. ⌃⌥⌘R or a Dock click stops. The window comes back, the preview lists the new Screenshots and the first one is selected.

### Reviewing and cleaning up

- ←/→ or a click moves through the Screenshots. Hover a thumbnail → ✕ → "Move to Trash?" → the file goes to the Trash and the next image (or the previous one, at the end) is selected.
- **Record again** → "Move N images to the Trash and record again?" → they go to the Trash and the Recording starts.

### Rename and delete

- **⋯** on a row → **Rename** → the row becomes editable → Enter renames the folder; the selection follows a renamed Tutorial or Project.
- **⋯** → **Move to Trash** → "Move the Project 'Python' and its 3 Tutorials to the Trash?" → the folder goes to the Trash; a selection inside it is cleared.

### Changes made in Finder

The tree and the selected Tutorial's images are re-read on the existing 1.5 s poll. A deleted selected Tutorial clears the selection; a deleted Projects folder shows the "Choose a Projects folder" notice.

## 3. Architecture

### Main process (`src/main`)

| Module                               | Kind                                             | Role                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Module                               | Kind                                             | Role                                                                                                                                                                                                                                                                                                                                                           |
| ---                                  | ---                                              | ---                                                                                                                                                                                                                                                                                                                                                            |
| `projects.ts`                        | new, pure (`fs/promises` direct, trash injected) | `createProjectsService({ getRoot, trash })`: the tree, create, rename, trash for Projects and Tutorials; `listImages`, `imagePath`, `trashImage`, `trashAllImages`; `tutorialPath`. Every incoming name is validated and must be an existing direct child, so no path ever leaves the Projects folder. `trash` is `shell.trashItem`, passed in from `index.ts` |
| `settings.ts`                        | changed                                          | Stores `{ projectsFolder, selectedTutorial, expandedProjects }`. `parseSettings` drops `outputFolder` and anything malformed. Follows renames and forgets trashed items                                                                                                                                                                                        |
| `outputFolder.ts` → `folderCheck.ts` | renamed                                          | `checkFolder(path)`: same rules, used for the Projects folder                                                                                                                                                                                                                                                                                                  |
| `tutorialRecording.ts`               | new, pure                                        | `checkReady()` (used by the recorder: permissions, Projects folder, a selected and empty Tutorial) and `recordAgain()` (confirm → `trashAllImages` → start). Keeps that logic out of `ipc.ts` so it is tested                                                                                                                                                  |
| `recorder.ts`                        | changed                                          | `toggle()` is replaced by `handleShortcut()`: stop when recording, `showWindow()` when idle. `hideWindow` hides every app window                                                                                                                                                                                                                               |
| `capture.ts`                         | changed                                          | Its folder dependency (`getFolder`) returns the selected Tutorial's folder, checked on every Capture; if it disappears mid-Recording, the existing error flow stops the Recording. Missing folders are no longer created                                                                                                                                       |
| `imageUrl.ts`                        | new, pure                                        | Builds and parses `tuto-image://<size>/<project>/<tutorial>/<file>?v=<mtime>` (`size` = `thumb` or `preview`)                                                                                                                                                                                                                                                  |
| `thumbnails.ts`                      | new, pure (render injected)                      | Resized copies (`thumb` 320 px, `preview` 1600 px wide), cached by path, version and size with a size limit, at most 4 renders at once                                                                                                                                                                                                                         |
| `imageProtocol.ts`                   | new, glue                                        | Registers the `tuto-image` scheme (before `app.whenReady`) and serves it: URL → `projects.imagePath` → thumbnail rendered with `sharp`                                                                                                                                                                                                                         |
| `windows.ts`                         | new, glue                                        | Owns the main window (now about 1000 × 680, minimum 760 × 520) and the single Settings window; `showMain()`, `openSettings()`, `hideAll()`, `sendToMain()`                                                                                                                                                                                                     |
| `menu.ts`                            | new, glue                                        | Application menu with **Settings… ⌘,**, plus the Edit menu that text fields need for ⌘C/⌘V                                                                                                                                                                                                                                                                     |
| `confirmElectron.ts`                 | new, glue                                        | `confirm({ message, detail, confirmLabel })` → `dialog.showMessageBox` → boolean                                                                                                                                                                                                                                                                               |
| `index.ts`                           | changed                                          | Wiring only; window code moves to `windows.ts`. Opens Settings at launch when not ready                                                                                                                                                                                                                                                                        |
| `ipc.ts`                             | changed                                          | New handlers (below), including the native ⋯ row menu (`Menu.popup`); validates every argument's shape and passes names to `projects.ts`, which validates them again                                                                                                                                                                                           |

### Shared (`src/shared`)

| File        | Role                                                                                                                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ipc.ts`    | Channels and types (below)                                                                                                                                                                                                               |
| `names.ts`  | new: `validateName(name, siblings)` → error message or null (trimmed, not empty, no `/` or `:`, not starting with `.`, at most 255 bytes, unique ignoring case). Used by the renderer for instant feedback and by main as the real check |

`SettingsState` becomes `{ projectsFolder, projectsFolderProblem, selectedTutorial, expandedProjects }`.

| `settings:get`                                              | invoke    | → `SettingsState`                                                                                   |

| `settings:select-tutorial`                                  | invoke    | `TutorialRef \| null` → `SettingsState`                                                             |

The CSP gets `img-src 'self' tuto-image:`.

### Renderer (`src/renderer`)

Two pages, built as two electron-vite renderer inputs:

```
src/renderer/
├─ index.html              main window: sidebar + preview
├─ settings.html           Settings window
├─ assets/                 base.css (tokens, dark mode) + one CSS file per module, linked from the HTML
└─ src/
   ├─ main.ts              main window entry: polls, holds state, wires modules (replaces renderer.ts)
   ├─ settings.ts          Settings window entry
   ├─ ui/                  dom helpers ($, el); the ⋯ menu itself is a native menu shown by main
   ├─ sidebar/             treeView.ts (pure: tree + selection + expanded + editing → rows), sidebar.ts (DOM, incl. the footer gear)
   ├─ tutorial-preview/    previewView.ts (pure: heading, empty state, selected image, the next selection for ←/→ and after a removal), preview.ts (DOM: large view, thumbnail strip, hover ✕, keys)
   ├─ recorder-bar/        recorderView.ts + status.ts (moved, extended for Start / Record again / disabled reasons), recorderBar.ts (DOM)
   ├─ permissions/         permissionView.ts (moved), permissionPanel.ts (DOM)
   └─ settings-window/     settingsView.ts (pure), settingsPage.ts (DOM)
```

Your module names map like this: _sidebar_ → `sidebar/`, _sidebar-settings_ → the gear in `sidebar/` plus `settings-window/`, _project-preview_ → `tutorial-preview/` (it previews a Tutorial). Each folder gets a README; `src/renderer/README.md` keeps only an overview and links.

Rules carried over: only DOM files touch the DOM and `window.api`; text through `textContent`; no inline scripts or styles. **Do not import CSS from TypeScript**: in dev, Vite injects it as `<style>` tags, which the CSP (`style-src 'self'`) blocks. Link CSS files from the HTML.

## 5. Testing

**Unit (Vitest, no Electron):**

- `names.ts`: every rule, case-insensitive duplicates, renaming to the same name with different case.
- `projects.ts` against real temporary folders, with a fake trash: tree and newest-first order, create, rename, trash, image filtering and order, refusing names that are not direct children (`..`, `a/b`).
- `imageUrl.ts`: round trip, encoded characters, rejecting paths outside the Projects folder and non-images.
- `settings.ts`: new shape, v0.1 file ignored, stale selection.
- `tutorialRecording.ts`: Start refused on a non-empty Tutorial or with none selected; Record again cancelled → nothing trashed; confirmed → trash then start.
- `recorder.ts`: `handleShortcut` idle vs recording.
- `treeView.ts`, `previewView.ts` (selection after removal, arrow keys at both ends, empty state), `recorderView.ts`, `status.ts`, `settingsView.ts`, `permissionView.ts`.

**Manual checklist (packaged app):**

- [ ] Upgrade from v0.1: Settings opens, old Output folder ignored
- [ ] Settings via the gear and ⌘,; opens by itself when a permission is missing
- [ ] Create a Project and a Tutorial; duplicate name (different case) refused
- [ ] Rename and trash from the ⋯ menu; trashed folders are in the Trash
- [ ] Sidebar newest first; selection and expanded Projects survive a restart
- [ ] Start on an empty Tutorial; Screenshots land in its folder; window and Settings window hidden while recording
- [ ] ⌃⌥⌘R stops; when idle it only shows the window; Dock click still stops and drops its Capture
- [ ] Record again: confirm, old images in the Trash, new Recording saved
- [ ] Preview: thumbnails scroll horizontally, ←/→ and clicks select, no chevrons, large image not clickable

## 6. Risks and mitigations

| Risk                                                                             | Mitigation                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Retina PNGs are several MB; loading them as thumbnails is slow                   | `thumb` and `preview` sizes made with `sharp`, cached in memory by path and modified time                                                                                                                  |
| The image protocol exposes files outside the Projects folder                     | `imageUrl.ts` rejects malformed URLs; `projects.imagePath` only accepts an image file listed directly in the Tutorial folder, and symbolic links are ignored; unit-tested with `..`, `/` and symlink cases |
| Names that differ only in case collide on APFS                                   | Uniqueness is checked ignoring case                                                                                                                                                                        |
| "Newest first" relies on folder creation time, which copying a folder resets     | Accepted; there is nowhere else to store an order ([ADR 0002](../docs/adr/0002-folders-are-the-only-record.md))                                                                                            |
| `shell.trashItem` fails on some volumes (network shares)                         | The error is shown in the window; nothing is deleted permanently as a fallback                                                                                                                             |
| The Settings window stays visible during a Recording and ends up in Screenshots  | `windows.hideAll()` on Start                                                                                                                                                                               |
| Record again moves images to the Trash, and the user then stops without clicking | Accepted (D5); the images are in the Trash                                                                                                                                                                 |
| Polling the whole tree every 1.5 s gets slow with many folders                   | Only the tree (two levels, `readdir` with file types) and the selected Tutorial's images are read; revisit with `fs.watch` if it shows up                                                                  |
| Dev mode CSS injection blocked by the CSP                                        | CSS linked from the HTML, never imported from TS                                                                                                                                                           |
