# tuto-record — v0.2.0 Implementation plan

The step-by-step build of [V0.2.0_PLAN.md](V0.2.0_PLAN.md). The design plan says **what** and **why** (decisions D1–D19); this file says **in what order, in which files, with which contracts and tests**. When the two disagree, fix the design plan first, then this file.

## How to use this file

- Work the milestones in order, and the steps inside a milestone in order. Every step ends with `npm run typecheck`, `npm run lint` and `npm test` passing.
- Each step lists the files it touches, the tests it adds or changes, and the READMEs to update in the same change ([CLAUDE.md documentation rule](../CLAUDE.md#documentation-rule)).
- When a milestone is finished, write a progress note under it, as in [MVP_PLAN.md](MVP_PLAN.md): `**Done (YYYY-MM-DD).** Notes: …`, including anything that turned out differently from this plan. If the manual check is still open, write `**Code done (date), manual check pending.**`
- From M1 until M4 recording is not possible: there is no way to select a Tutorial before M2 and no Start button before M4. That is expected. The preview (M3) is tested with images copied into a Tutorial folder in Finder.

## Conventions used below

- **Pure** means the module takes its dependencies as arguments and is unit-tested without `electron`. **Glue** means it calls Electron or the OS and is checked by hand ([src/main/README.md](../src/main/README.md)).
- Tests stay flat in `tests/`, named after the module (`tests/projects.test.ts`).
- Main-process modules that touch the file system use `fs/promises` directly and are tested against real temporary folders, like `settings.ts` today. Only Electron calls (`shell.trashItem`, `dialog`, `protocol`, `Menu`) are injected or kept in glue files.

## Shared contracts

Final shape of the new types in [`src/shared/ipc.ts`](../src/shared/ipc.ts). Each milestone adds the parts it needs.

```ts
export interface TutorialRef {
  project: string
  tutorial: string
}

export interface TutorialNode {
  name: string
}

export interface ProjectNode {
  name: string
  /** Newest first, by folder creation time. */
  tutorials: TutorialNode[]
}

export interface ImageItem {
  file: string
  /** tuto-image:// URLs; they change when the file changes. */
  thumbUrl: string
  previewUrl: string
}

/** Result of a create or rename: null when it worked, otherwise a message for the inline error. */
export interface NameResult {
  error: string | null
}

export type RowAction = 'rename' | 'trash'

export interface SettingsState {
  projectsFolder: string | null
  /** Why the Projects folder cannot be used (deleted, not writable), or null. */

  /** Null when nothing is selected or the selected Tutorial's folder no longer exists. */

  expandedProjects: string[]
}
```

`RecorderStatus` and `PermissionsStatus` are unchanged.

### 1.2 Settings: the new shape

`src/main/settings.ts`:

```ts

  selectedTutorial: TutorialRef | null
  expandedProjects: string[]
```

- Tests (`tests/settings.test.ts`, rewritten): defaults; v0.1 file ignored; each malformed field dropped on its own; round trip across restarts; `setProjectsFolder` clears selection and expansion; `followProjectRename` updates `selectedTutorial.project` and `expandedProjects`; `followTutorialRename` only when the ref matches; `forget*`; a deleted selected Tutorial reads as `null`; the atomic write still leaves no `.tmp`.

## M2 — Projects and Tutorials

**Result:** the two-pane window. The sidebar shows the Projects tree; Projects and Tutorials can be created, renamed and moved to the Trash. The right pane shows the heading and a placeholder until M3.

### 2.1 Names

New `src/shared/names.ts` (pure, no imports):

```ts
/**
 * Null when `name` can be used for a folder among `siblings`, otherwise a short message.
 * `current` is the item's own name when renaming, so a case-only change ("git" → "Git") is allowed.
 */
export function validateName(name: string, siblings: string[], current?: string): string | null
```

- Rules, checked on the trimmed name, in this order: not empty ("Enter a name."); no `/` or `:` ("Names can't contain / or :."); does not start with `.` ("Names can't start with a dot."); at most 255 UTF-8 bytes ("That name is too long."); not equal to a sibling ignoring case, other than `current` ("That name is already used.").
- Tests: `tests/names.test.ts`: every rule, trimming, case-only rename, multi-byte characters near the length limit.
- Docs: `src/shared/README.md` allows dependency-free pure functions in `shared/` and lists `names.ts`.

### 2.2 Projects service

New `src/main/projects.ts` (pure apart from `fs/promises`):

```ts
export interface ProjectsDeps {
  /** The Projects folder, or throws with a readable message when it is missing or unusable. */
  getRoot(): Promise<string>
  /** Moves a file or folder to the Trash. */
  trash(path: string): Promise<void>
}

export interface ProjectsService {
  listTree(): Promise<ProjectNode[]>
  createProject(name: string): Promise<NameResult>
  createTutorial(project: string, name: string): Promise<NameResult>
  renameProject(project: string, to: string): Promise<NameResult>
  renameTutorial(ref: TutorialRef, to: string): Promise<NameResult>
  /** For the confirmation message. */
  countTutorials(project: string): Promise<number>
  trashProject(project: string): Promise<void>
  trashTutorial(ref: TutorialRef): Promise<void>
  /** The Tutorial's folder; throws when the ref is invalid or the folder does not exist. */
  tutorialPath(ref: TutorialRef): Promise<string>
}
export function createProjectsService(deps: ProjectsDeps): ProjectsService
```

- `listTree`: direct subfolders only (`readdir` with `withFileTypes`), skipping names that start with `.`; both levels sorted by `stat().birthtimeMs`, newest first, then by name. A Project that can't be read is listed with no Tutorials instead of failing the whole tree.
- Every incoming name is checked with `validateName`'s character rules, and an existing name must be a direct child found by `readdir` (never trusted by joining paths), so `..`, `a/b` and symlinks are refused with an error.
- Create uses `mkdir` without `recursive`, so a race with Finder reports "That name is already used." Rename uses `rename`.
- Tests: `tests/projects.test.ts` against a real temp folder, with a fake `trash` that records paths: newest-first order (create folders about 20 ms apart), hidden folders and plain files skipped, every `NameResult` error, case-only rename, `..` and `/` refused, the path given to `trash`, `countTutorials`.

### 2.3 IPC, selection and the row menu

- `index.ts`: `createProjectsService({ getRoot, trash: (p) => shell.trashItem(p) })`; `getRoot` reads `settings.get()` and throws its problem.
- New `src/main/confirmElectron.ts` (glue): `confirm({ message, detail, confirmLabel }): Promise<boolean>`: `dialog.showMessageBox` on the focused window, buttons `[confirmLabel, 'Cancel']`, `cancelId: 1`, and `defaultId: 1` so Return does not trash by accident.
- `ipc.ts` handlers:
  - `projects:list` → `listTree()`; `[]` when there is no usable Projects folder.
  - `projects:create`, `tutorials:create` → `NameResult`; a new Project is added to `expandedProjects`.
  - `projects:rename`, `tutorials:rename` → `NameResult`, then `settings.followProjectRename` / `followTutorialRename`.
  - `projects:trash` → confirm ("Move the Project "Python" and its 3 Tutorials to the Trash?", `confirmLabel: 'Move to Trash'`) → `trashProject` → `settings.forgetProject` → `true`; cancelled → `false`. `tutorials:trash` the same ("Move the Tutorial "…" and its screenshots to the Trash?").
  - `settings:select-tutorial`, `settings:set-expanded`, `tutorial:open-in-finder` (`shell.openPath(await projects.tutorialPath(ref))`).
  - `menu:row-actions` `{ x, y }` → pops a native `Menu` with **Rename** and **Move to Trash** at that point in the sender's window; resolves to the chosen `RowAction`, or `null` when the menu closes without a choice (`Menu.popup`'s `callback`). The ⋯ button is DOM, the menu itself native, matching the native confirmations (D17) with no DOM menu code.
- A failing `trashItem` (for example on a network volume) rejects the invoke; the renderer shows the message in the status line.

### 2.4 Sidebar module

`src/renderer/src/sidebar/`:

- Tests: `tests/treeView.test.ts`: order kept from main, expansion, selection, each editing kind, stale expanded names.
- Docs: `sidebar/README.md`; `ui/README.md` if `dom.ts` grew.

## M3 — Preview

**Result:** the selected Tutorial's images in a large view and a horizontal thumbnail strip, navigable with ←/→ and clicks. Tested with images copied into a Tutorial folder in Finder.

### 3.1 Images on disk

- New `src/shared/images.ts`: `IMAGE_EXTENSIONS = ['png', 'jpg', 'jpeg', 'gif', 'webp']`, `isImageFile(name)` (extension compared ignoring case, name not starting with `.`).
- `projects.ts`:
  - `listImages(ref): Promise<{ file: string; version: number }[]>`: image files directly in the Tutorial folder, sorted by name with `localeCompare(…, undefined, { numeric: true })` (D12); `version` is `mtimeMs`.
  - `imagePath(ref, file): Promise<string>`: the file must be an image and a direct child, and its `realpath` must be inside the real Projects folder (so a symlink can't point out); otherwise it throws.
- Tests in `tests/projects.test.ts`: filtering, order, subfolders ignored, `imagePath` refuses `..`, `a/b`, a non-image and a symlink out of the root.

### 3.2 Image URLs

New `src/main/imageUrl.ts` (pure):

```ts
export type ImageSize = 'thumb' | 'preview'
export const IMAGE_SCHEME = 'tuto-image'
/** tuto-image://thumb/<project>/<tutorial>/<file>?v=<version>, each segment URI-encoded. */
export function imageUrl(size: ImageSize, ref: TutorialRef, file: string, version: number): string
export function parseImageUrl(
  url: string
): { size: ImageSize; ref: TutorialRef; file: string } | null
```

- Parsing rejects other schemes and hosts, a wrong number of segments, and segments that decode to `.` or `..` or contain `/`.
- Tests: `tests/imageUrl.test.ts`: round trip with spaces, `#`, `%`, `?` and emoji; every rejection.

### 3.3 Thumbnails

New `src/main/thumbnails.ts` (pure):

```ts
export interface ThumbnailDeps {
  /** Reads the image at `path` and returns it resized to `width` px wide (never enlarged). */
  render(path: string, width: number): Promise<Buffer>
}
export function createThumbnailer(
  deps: ThumbnailDeps,
  options?: { maxEntries?: number; concurrency?: number }
): (path: string, version: number, size: ImageSize) => Promise<Buffer>
```

- Widths: `thumb` 320 px, `preview` 1600 px. Cache key `path + version + size`; least-recently-used eviction at `maxEntries` (default 300); at most `concurrency` renders at once (default 4); a key requested again while it renders shares that render.
- Tests: `tests/thumbnails.test.ts` with a fake `render`: cache hit, a new version renders again, eviction, the concurrency limit, the shared in-flight render.

### 3.4 Protocol

New `src/main/imageProtocol.ts` (glue):

- `registerImageScheme()`: `protocol.registerSchemesAsPrivileged([{ scheme: 'tuto-image', privileges: { standard: true, secure: true } }])`. **It must run before `app.whenReady()`**, so `index.ts` calls it at the top level.
- `handleImages(projects, thumbnailer)`, called inside `whenReady`: `protocol.handle('tuto-image', …)` → `parseImageUrl` → `projects.imagePath` → thumbnailer → `new Response(buffer, { headers: { 'content-type': 'image/webp' } })`. Anything invalid gets a 404 whose body never contains a path.
- The real `render` is `sharp(path).resize({ width, withoutEnlargement: true }).webp({ quality: 90 }).toBuffer()`.
- CSP in `index.html`: `img-src 'self' tuto-image:`.
- `ipc.ts`: `images:list` → `ImageItem[]` built with `imageUrl`. The `version` makes a changed file a new URL, so neither Chromium nor the cache shows a stale image.

### 3.5 Preview module

`src/renderer/src/tutorial-preview/`:

- `previewView.ts` (pure), next to `heading()`:
  - `buildPreview(images, selectedFile)` → `{ state: 'none' | 'empty' | 'images', selectedIndex, large: ImageItem | null }`; a `selectedFile` that is not in the list selects the first image.
  - `moveSelection(images, selectedFile, 'left' | 'right')` → file; stops at the ends (D11).
  - `selectionAfterRemoval(images, removedFile)` → the next file, the previous one at the end, or null (used in M5).
- `preview.ts` (DOM): the large `<img>` (`previewUrl`); the strip of `<button>` thumbnails (`thumbUrl`, `loading="lazy"`) in a horizontally scrolling row; the selected one outlined and brought into view with `scrollIntoView({ inline: 'nearest', block: 'nearest' })`. The large image has no click handler and there are no chevrons (D10). The strip is rebuilt only when the list of `file + version` changed, which keeps the scroll position and avoids flicker. Empty state: "No screenshots yet" and a one-line explanation (M4 adds the Start button).
- Keys on `document`: ←/→ move the selection; ignored while focus is in a text field.
- `main.ts` adds `images:list` for the selected Tutorial to the 1.5 s poll.
- CSS: `assets/preview.css` (large image `object-fit: contain`, strip `overflow-x: auto`, thumbnails about 180 × 112).
- Tests: `tests/previewView.test.ts`.
- Docs: `tutorial-preview/README.md`; `src/main/README.md` gets a "Preview images" section (protocol, URL format, cache, the path checks).

**✅ Check:** 50 Retina PNGs copied into a Tutorial open without visible lag and the strip scrolls smoothly; ←/→ and clicks select and keep the selection in view; a PNG and a JPG appear in name order; a file edited in Finder shows its new content; the URL `tuto-image://thumb/..%2F..` typed into DevTools returns 404.

## M4 — Recording into a Tutorial

**Result:** Start recording on an empty Tutorial saves there; Record again replaces; ⌃⌥⌘R only stops.

### 4.1 Capture destination

- `capture.ts`: rename the dependency `getOutputFolder` → `getFolder` ("the folder for this Capture, or throws"); comments say Tutorial folder.
- `captureElectron.ts`: `getFolder` = `settings.get()` → selected Tutorial → `projects.tutorialPath(ref)`; throws "No Tutorial is selected." or the path error. It is resolved for every Capture, so a Tutorial renamed or deleted in Finder mid-Recording fails the next Capture and the existing error flow stops the Recording.
- `writeFile` in `captureElectron.ts` no longer creates missing folders (remove the `mkdir`): the folder was just checked, and re-creating a Tutorial the user deleted would be wrong.
- Tests: `tests/capture.test.ts` uses `getFolder`.

### 4.2 Tutorial recording

`projects.ts` gains `trashAllImages(ref)` (every `listImages` file, through `imagePath`). New `src/main/tutorialRecording.ts` (pure):

```ts
export interface TutorialRecordingDeps {
  permissionsGranted(): boolean
  getSettings(): Promise<SettingsState>
  countImages(ref: TutorialRef): Promise<number>
  trashAllImages(ref: TutorialRef): Promise<void>
  confirm(request: { message: string; detail: string; confirmLabel: string }): Promise<boolean>
  /** recorder.start, passed as a closure because the recorder is created after this. */
  startRecorder(): Promise<void>
}

export interface TutorialRecording {
  /** The recorder's checkReady: null, or why recording can't start. */
  checkReady(): Promise<string | null>
  /** Confirms, empties the Tutorial, then starts. Resolves false if cancelled. */
  recordAgain(): Promise<boolean>
}
export function createTutorialRecording(deps: TutorialRecordingDeps): TutorialRecording
```

- `checkReady` messages, in order: "Grant both permissions first." · "Choose a Projects folder first." · the folder problem · "Select a Tutorial first." · "This Tutorial already has screenshots. Use Record again." (D4).
- `recordAgain`: no Tutorial selected → `false`; confirm "Move 12 images to the Trash and record again?" (`confirmLabel: 'Record again'`); cancelled → `false`, nothing trashed; confirmed → `trashAllImages` → `startRecorder()` → `true` (D5: emptied when Start is pressed). If trashing fails, the Recording does not start and the error propagates.
